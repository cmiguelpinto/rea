D01 · Trace an Electron CSV export

Which files handle the Notes app’s Export notes action, and how does the renderer reach the CSV writer? The checked-in six-file fixture is a static analysis target; it does not require Electron to launch.

Run the pinned npm package from a working directory outside the repository checkout. Replace /absolute/path/to/rea with the checkout's absolute path; output JSON files are written to the current directory. This avoids npx resolving a checkout with the same package name and version: 

npx -y rea-agents@6.4.0 analyze-javascript-application /absolute/path/to/rea/website/public/examples/notes-electron --json > application-evidence.json
node --input-type=module -e '
import { readFileSync, writeFileSync } from "node:fs";
const application = JSON.parse(readFileSync("application-evidence.json", "utf8"));
writeFileSync("feature-trace.json", JSON.stringify({
  application,
  seed: { kind: "string", value: "notes:export" },
  direction: "both"
}));'
node --input-type=module -e '
import { readFileSync, writeFileSync } from "node:fs";
const application = JSON.parse(readFileSync("application-evidence.json", "utf8"));
writeFileSync("semantic-trace.json", JSON.stringify({
  application,
  query: { seed: { kind: "property", name: "invoke" }, direction: "forward-influence" }
}));'
npx -y rea-agents@6.4.0 trace-application-feature ./feature-trace.json --json
npx -y rea-agents@6.4.0 trace-javascript-semantics ./semantic-trace.json --json

To run the checkout's source instead, work from its root after npm ci and npm run build, and use node scripts/rea.mjs in place of each pinned npx command.

The trace connects the renderer, preload bridge, literal notes:export channel and main-process handler. On the recorded run, the application graph contained 29 nodes and 42 edges; the feature trace covered all 29 nodes and 42 edges. A semantic query seeded by the invoke property was ambiguous, with one relevant unknown and partial coverage. A literal semantic query for notes:export found no seed; the exact IPC channel comes from the application graph. The source-backed path is renderer.js to preload.js to main.js and csv.js: the renderer calls window.notes.exportCsv(), the preload invokes notes:export, and the main handler writes notes.csv under Electron's Downloads path. The CSV writer emits the id,title header and note rows; the handler returns the destination for the renderer's status message. Static analysis does not establish that a click or file write occurred, or resolve the actual Downloads path.

The recorded source-checkout run also required the package-matched Windows native artifact. The Windows build lane uses Linux and MinGW-w64; released packages bundle the matching artifact. See the Windows native verification notes before repeating the analysis from a Windows source checkout.

The agent evaluation now asks for the analysis, feature trace and semantic query in that order. This host did not produce a usable Codex transcript, so the requested agent interaction remains unverified. No agent answer is presented as a captured result. Compare the static findings with the JavaScript and Electron guide.

D02 · Find a native function

Which function prints REA_C_ENTRY, and which calls lead from it to the leaf calculation? The source-owned C fixture is tests/conformance/c/fixture.c. Its rea_entry function calls rea_branch, which calls rea_leaf.

Fixture generation is supported on macOS and Linux with a C toolchain. It writes ignored files under build/conformance/ and verifies their source and binary hashes: 

npm run build:fixtures
npm run verify:fixtures

With Ghidra configured, the equivalent CLI investigation uses the same target and provider for each standalone command: 

node scripts/rea.mjs search build/conformance/c "REA_C_ENTRY" --provider ghidra --json
node scripts/rea.mjs function build/conformance/c rea_entry --provider ghidra --json
node scripts/rea.mjs function build/conformance/c rea_branch --provider ghidra --json
node scripts/rea.mjs xrefs build/conformance/c rea_entry --provider ghidra --json

The rea_branch query shows the next call to rea_leaf. CLI xrefs accepts a symbol name and resolves it to an address; the MCP operation takes an address (Ghidra requires it explicitly). In MCP, open the binary, search for the marker and procedures, inspect rea_entry and rea_branch, pass the resolved address to xrefs, then call close_binary. The MCP lifecycle must report successful cleanup. The CLI commands use separate processes and release their own analysis resources when each command exits.

This Windows host has no configured Ghidra, IDA or Hopper provider, so no pseudocode, assembly or reference result is claimed. The provider run remains blocked until one of those bring-your-own engines is available. See the provider setup guide and native CLI guide.

D03 · Compare a browser action

What changes after clicking Export notes? The real-browser verifier starts its source-owned loopback page in Chrome, clicks the button, waits for an explicit ready state and captures the DOM. It repeats the same steps for a changed variant, then compares the two captures with the public CLI.

From the repository root, install the pinned dependencies with npm ci. Linux and macOS use the verifier’s standard Chrome paths. On Windows, set REA_BROWSER_EXECUTABLE to the installed Chrome executable before running the command: 

$env:REA_BROWSER_EXECUTABLE = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
npm run verify:browser

The baseline displays Exported 2 notes; the changed variant displays Exported 3 notes. The captures align by their step IDs, the comparison reports changed, and the result step contains one changed DOM artifact. This shows a controlled fixture difference, not behavior from an external site.

The verified run used Chrome 154. REA terminated the browser processes it launched, removed their temporary profiles, closed the loopback fixture and removed the temporary comparison inputs. The source and verifier are in scripts/verify-real-browser.mjs. The browser guide explains the MCP capture contract and its worked example.
